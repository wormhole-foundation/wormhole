# testgen — Solana watcher `processTransaction()` input builder

A dev/builder API for constructing realistic inputs to
`SolanaWatcher.processTransaction()` across every code path it handles, without
hand-managing account-key indices.

## What it produces

A `Bundle` whose JSON maps directly onto the watcher's inputs:

- `transaction` → decodes into `solana.Transaction`
- `meta` → decodes into `rpc.TransactionMeta`
- `accounts` → a list of `getAccountInfo` responses (`pubkey`, `owner`,
  base64 `data`, …) to feed a mock for the account-based path

By default transactions are **legacy** (no Address Lookup Tables), so account indices
equal the static `accountKeys` list verbatim. Set `Config.UseLookupTable` to instead emit
a **versioned (v0)** transaction: at `Build()` the non-program, non-signer accounts move
into a single Address Lookup Table (message accounts writable, fillers readonly), the
instruction indices are rewritten to the composite `static → writable-loaded →
readonly-loaded` ordering, and the ALT account itself is synthesized into `Accounts`
(owned by the ALT program) so the watcher fetches and resolves it. Byte encoding reuses the
watcher's own exported borsh structs (`PostMessageData`, `ShimPostMessageData`,
`ShimMessageEventData`, `MessagePublicationAccount`), so generated bytes can never drift
from what the watcher deserializes (asserted against known-good vectors in
`builder_test.go`).

## Degrees of freedom

| Knob | How |
| --- | --- |
| **Location** — outer / inner | `Location: Outer` (top-level instruction) or `Inner` (behind a wrapper program's inner-instruction set) |
| **Type** — regular / shim / close / mix | `AddRegular`, `AddShim`, `AddClose`; call several in one builder to mix |
| **Message** — reliable / unreliable | `Kind: PostMessage` (0x01/`msg`) or `PostMessageUnreliable` (0x08/`msu`) |
| **Wormhole fields** | `WormholeFields{Nonce, Payload, Commitment, Sequence, EmitterChain, EmitterAddress, Timestamp}` |
| **Account content** | `AccountContent{Prefix, Owner, VaaVersion, RawConsistency, EmitterAuthority, MessageStatus, Gap, SubmissionTime}` — for bad-prefix / wrong-owner / not-finalized accounts |
| **Shim topology** | `Topology: Direct` (shim post top-level) or `Integrator` (all three inner) |
| **Shim ordering** | `Ordering: []ShimPart{...}` — reorder / duplicate the three parts to exercise the `shimProcessRest` invariant |

`Commitment`'s zero value (`CommitmentDefault`) resolves to the watcher's own
commitment, so cases are observable unless a mismatch is requested. The instruction
scale (`0`=confirmed, `1`=finalized) and account scale (`1`=confirmed, `32`=finalized)
are mapped internally. `AddClose` forces the transaction's reobservation flag true.

## Usage — library

```go
b := testgen.NewBuilder(testgen.Config{
    Contract:          coreProgramID,
    ShimContract:      shimProgramID, // omit to disable shim handling
    WatcherCommitment: rpc.CommitmentFinalized,
    Slot:              42,
})
b.AddRegular(testgen.RegularSpec{
    Location: testgen.Outer,
    Kind:     testgen.PostMessage,
    Msg:      testgen.WormholeFields{Nonce: 7, Payload: []byte("hi"), Sequence: 99, EmitterChain: uint16(vaa.ChainIDSolana), EmitterAddress: emitter},
})
b.AddShim(testgen.ShimSpec{Topology: testgen.Integrator, Msg: testgen.WormholeFields{Nonce: 8, Payload: []byte("world")}})
bundle, err := b.Build()
data, _ := json.MarshalIndent(bundle, "", "  ")
```

## Usage — CLI (emit the scenario matrix)

```sh
go run ./pkg/watchers/solana/testgen/cmd --out ./pkg/watchers/solana/testdata/generated_bundles.json
```

Writes a single **minified** JSON file holding an array of **every** synthetic bundle
across all matrices (the command always emits the full set).
Cases cover regular/shim/close × outer/inner × reliable/unreliable, shim-ordering and
account-content edge cases, integer boundary sweeps, situation edge cases, 40 triplet
transactions that mix three (type, location) variants each, failed-transaction cases
(`txfailed_*`, one per type × location) where `meta.Err` is set so
`validateTransactionMeta` rejects the transaction and nothing is published, and
lookup-table cases (`lookuptable_*`, regular/close × outer/inner) that reach their message
account through a synthesized Address Lookup Table so the watcher's v0 ALT-resolution path
is exercised.

### Two fixture files

The replay matrix is split across two minified files, both read by `bundle_replay_test.go`:

- **`testdata/generated_bundles.json`** — the synthetic matrix above, produced by this CLI.
- **`testdata/real_bundles.json`** — live-collected real Solana transactions, produced by
  `collect_wormhole_solana_logs.py` (each `real_*` bundle).

Keeping them separate means regenerating the synthetic matrix (which overwrites its file
wholesale) never disturbs the live-collected fixtures, and vice versa. A recorded
`expected` block is written back into whichever file the bundle came from.

The replay test reads both files and records a reproducible output signature — message
count plus per-message digests — into an `expected` block on each bundle. The recorded
hashes are the **reobservation** output (the complete set). Every run replays each bundle
three ways and checks against that hash list:

- **Reobservation** (`processTransaction`, `isReobservation=true`) — exact match: every
  recorded digest must appear and none extra.
- **Observation** (`processTransaction`, `isReobservation=false`) — subset: a digest may
  legitimately be missing (e.g. close-message events are only processed on
  reobservation), but nothing outside the recorded set may appear.
- **Account fetch** (`fetchMessageAccount` on each core post_message message account) —
  subset: the by-account entry point used by reobservation must only emit recorded
  hashes. Wrong-CPI instructions (non-core program) and failed transactions (rolled
  back, so no committed account) select no account and emit nothing.

## Loading a bundle into a test

```go
var env struct {
    Transaction json.RawMessage `json:"transaction"`
    Meta        json.RawMessage `json:"meta"`
    Accounts    []struct {
        Pubkey solana.PublicKey `json:"pubkey"`
        Owner  solana.PublicKey `json:"owner"`
        Data   []string         `json:"data"` // [base64, "base64"]
    } `json:"accounts"`
}
json.Unmarshal(bundleJSON, &env)

var tx solana.Transaction
json.Unmarshal(env.Transaction, &tx)
var meta rpc.TransactionMeta
json.Unmarshal(env.Meta, &meta)

// Register env.Accounts (pubkey -> owner + base64-decoded data) with a getAccountInfo
// mock, then call the watcher: s.processTransaction(ctx, rpcClient, &tx, &meta, bundle.Slot, bundle.IsReobservation)
```

The account-based path fetches the message account by RPC, so wire `accounts` into a
`getAccountInfo` mock (see `mockRPCServer` in `client_test.go`). Shim and close paths
carry their data inline in the instructions and need no account mock.
```
